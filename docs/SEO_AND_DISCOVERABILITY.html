The analytics code is ready and inert until this is set. You can't improve what you can't measure.

  1. In Google Analytics, create a GA4 property + a Web data stream for tinypartyportal.com. Copy the Measurement ID (G-XXXXXXXXXX).
  2. Add it to your .env (and your hosting/CI env):

  3. Rebuild & deploy. Page views (including invite views) and the referral UTMs will start flowing automatically.
Tip: in GA4, mark a "signup" conversion event so you can see how many invite-referred visitors actually create an account.

P2 Add prerendering / static HTML for marketing pages~half day

The site is a client-rendered SPA. Google can render JS, but static HTML indexes faster and more reliably — and it's a prerequisite for the blog ranking well. The shared-event links already use the eventShareMeta Cloud Function for this; the marketing pages don't.

Options, easiest first:

  • Prerender at build time (e.g. vite-plugin-prerender / puppeteer) for the handful of public routes (/, /contact, /privacy, /terms, future /blog/*). Lowest disruption.
  • Migrate marketing pages to a meta-framework (Astro for content, or Next.js) — bigger lift, best long-term if content becomes central.

I can implement the build-time prerender option without touching the app/dashboard code.

P2 Sharpen the referral loop~1 hr

UTMs are now in place. Next: every invite is seen by 10–30 parents who are your exact target. Worth testing a warmer call to action than a quiet "Powered by" — e.g. a small "Plan your own party free →" chip on guest pages. A/B it via GA4 once analytics is live. (This is a product/brand call, so left for your decision rather than changed unilaterally.)

P2 Off-site presence & backlinks YOUongoing

  • Product Hunt launch — a burst of traffic plus a permanent, high-authority backlink.
  • Australian parenting communities — mum Facebook groups, parenting forums, local "what's on for kids" directories. Relevant backlinks remain a core ranking signal.
  • SaaS / app directories — AlternativeTo, Capterra, "best birthday invitation app" roundup articles.
  • Google Business Profile if you ever want local/AU visibility.

P3 Bundle code-splitting~2 hr

The build warns about chunks over 500 KB — the main bundle (~737 KB) and PrintableInvitePage (~406 KB, from html2canvas/jspdf). Large JS slows mobile load, which feeds Core Web Vitals (a ranking factor). The print/PDF libraries especially should be dynamically imported so only the print page pays for them.

P3 Richer schema once you have proof~1 hr each

  • AggregateRating / Review schema once you collect testimonials — earns star ratings in search results.
  • BreadcrumbList schema once the blog/site has depth.
  • Per-article Article schema on blog posts.
